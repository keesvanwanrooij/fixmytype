# Word-first export evidence

Checkpoint: `15c5081`. Date: 2026-09-06. Scope: [Word-first delivery](../word-first-delivery.md).

## Red and green

- `npx vitest run tests/word-export.test.ts` first failed because the export module did not exist. Six tests now pass for Unicode, paragraphs, tabs, escaped markup, invalid data, cancellation, overlapping operations, existing files and opening errors.
- `npm test` passed 84 tests across 20 files after cleanup. `npm run lint` and the production build passed. The cleanup replaced a control-character regular expression with a direct XML-character validator.
- `npm run test:word` passed real Electron/preload/main interaction. The native dialog and default-app launcher are controlled fixtures. Cancellation keeps the draft. Later typing does not enter an earlier snapshot. Existing bytes are preserved when another save selects the same name. A stale snapshot has visible feedback.
- The same command opened the generated synthetic `.docx` read-only in a separate installed Microsoft Word process. Word returned the exact expected NL/EN text, emoji, tab, spaces and blank paragraphs. It reported no fields or hyperlinks. The fixture closed its own document and Word instance.
- The first Word fixture exposed incorrect HWND lookup and COM Quit arguments in test code. Both were corrected. Orphaned empty test processes were identified by their exact process ID/start time and stopped. No user document was opened, changed or closed.
- An actual Electron screenshot of the export panel was inspected. Controls have spacing and readable labels. This does not replace physical Windows text-scaling acceptance.
- The pinned `docx@9.7.1` writer is MIT-licensed and runs in main. `jszip@3.10.1` is a direct development dependency for archive assertions. Installation reported zero known audit vulnerabilities. No dependency install scripts were newly approved.

## Boundaries

The saved document is a snapshot. Word editing, typing interception and direct insertion are not connected. `shell.openPath` success means Windows accepted the open request, not that Word finished opening. Exports follow the user's chosen folder and its sync/retention policy. The default association launch is fixture-controlled; the real Word round-trip is separate.
