# Repair cancellation and response limits

Date: 2026-09-06. Checkpoint: `db4168a`. Scope: [phase 6](../phases/06-selected-text-repair.md).

## Behavioural evidence

Four new provider checks failed against the previous implementation: extra response fields were accepted, a pre-cancelled request contacted the provider, cancellation during response reading still returned text, and an unbounded stream did not stop. The implementation now rejects all four paths. Empty and excessive replacement, malformed data and runtime disconnect checks also pass.

`npm run test:repair` uses the real Electron UI and preload with controlled job completion. AI Off discards a late result. Ignore leaves the original unchanged. A disconnected provider displays failure without inserting text. A saved vocabulary change discards a response requested with the earlier vocabulary. Its initial run found a waiting message that remained after cancellation; the UI now clears it.

The cleanup uses one bounded response reader for both metadata and generation. It removes abort listeners and releases stream readers. It does not expose raw provider parse errors. The test's `SYNTHETIC_RUNTIME_DISCONNECT` stderr entry is deliberate, contains no user text and is followed by successful UI assertions.

## Commands

- `npm test` passed 89 tests in 20 files after cleanup.
- `npm run lint` and `npm run build` passed. The renderer was rebuilt after the waiting-message fix.
- `npm run test:repair` passed all controlled failure paths.
- `npm run test:workflow` passed real local inference and fake-microphone Whisper transcription, including concurrent typing, Accept, Undo and released tracks.

Direct Word editing, immediate provider cancellation for every focus transition, physical microphone acceptance and end-user latency targets remain open. The running user Ollama service was not stopped to create a fault; disconnection is a controlled test fixture.
